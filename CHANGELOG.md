# Changelog — Graph Connectivity Tests

All notable changes are listed here. Versions follow MAJOR.MINOR.PATCH (see the developer guide, appendix C).
Author: Nicolas Fabert.

## [1.0.0] — 2026-11-09

First version. Microsoft Graph connectivity tests in the user context, with Microsoft Graph instead of EWS, with the structure and the standards of Web Services Client for Exchange.

### Added
- **Inputs of the free/busy test**: `Target.SourceMailbox` / `-SourceMailbox`; `Target.TargetMailboxes` / `-TargetMailbox` (up to 20 targets in one run); `Target.OnPremisesHost` / `-OnPremisesHost`; `Target.SkipOnPremisesChecks` / `-SkipOnPremisesChecks`; the interactive OAuth sign-in of the source user (sign-in window or device code, MFA and Conditional Access included).
- The source asks and Exchange finds the target and calls the other side. The test runs from the workstation, signed in as the source, through Microsoft Graph `getSchedule` — and through EWS `GetUserAvailability` on-premises when the source mailbox is there — and shows every request and response.
- **Tests** `FreeBusy` (default), `MailboxServices`, `Provisioning`, `DomainDns` and `All` (every test, one sign-in).
- **No application to register**: the user signs in with *Microsoft Office* (`d3590ed6-52b3-4102-aeff-aad2292ab01c`), a public client of Microsoft pre-authorized for Microsoft Graph in every tenant (`.default`, no consent). `Identity.ClientId` `GraphCommandLineTools` (named permissions, consent once) or your own multi-tenant application; `Identity.Scopes` to ask permissions by name. Sign-in window (Microsoft Edge or Google Chrome, temporary profile, authorization code with PKCE) or device code (`Test.SignIn Auto|Window|DeviceCode`); automatic fallback to the device code when the window cannot open or the redirect URI is refused.
- **Application context** (`Identity.Context Application`): client credentials with a certificate of the certificate store (signed assertion), `/users/<source>` instead of `/me`, for scheduled tasks.
- **Discovery** without sign-in: Entra ID tenant (OpenID configuration) and user realm of each domain, Autodiscover v2 of Exchange Online then of the domain; the location of each mailbox and the **path** of each request: `SameOrganisation`, `CloudToOnPremises`, `OnPremisesToCloud`, `OnPremises`, `CrossOrganisation`.
- **On-premises endpoint**: public DNS, TLS certificate (expiry warning), and what `/EWS/Exchange.asmx` and `/autodiscover/autodiscover.svc` answer without credentials — `401` with `Bearer`, the tenant among `trusted_issuers`; redirect or sign-in page reported as a reverse proxy with pre-authentication. `-SkipOnPremisesChecks` skips it.
- **Free/busy**: the signed-in user and its mailbox (Exchange Online, or on-premises through EWS with the token of hybrid modern authentication from the same sign-in, the current Windows account, or an account typed — `Identity.OnPremisesAuthentication Credential`, `-OnPremisesCredential`, NTLM, Negotiate or Basic, `Auto` taking the best scheme EWS offers; the password stays in memory, the trace shows the user name only), the targets in the directory (mail, UPN, secondary address) and their MailTips (internal, external partner, external), then `getSchedule` / `GetUserAvailability` for all the targets: the detail the source may see, calendar items, working hours and time zone; for each Availability error, **its cause for the path** and what to check (`ErrorMailRecipientNotFound`, `ErrorAvailabilityConfigNotFound`, `ErrorNoFreeBusyAccess`, `ErrorProxyRequestProcessingFailed` and the proxy family with the remote `401` / `403` / `404` / `5xx` / connection / TLS / federation / Autodiscover error, `ErrorFreeBusyGenerationFailed`, group and throttling errors).
- **Window progress**: a timeline of the stages (node and result per stage, the stages without problem folded) with the diagnostics of each check (details, HTTP exchanges with their request and response), a diagnostic log in time order, a *Diagnostics* switch and *Copy the log*; the colours of the other consoles of the author (status colours, neutral notice, the accent of the tool on the selected view).
- **Administrator checks** (`-AdminChecks`, optional, best effort): `Get-IntraOrganizationConnector`, `Get-OrganizationRelationship`, `Get-AvailabilityAddressSpace` read through the Exchange Online administration API with the client of `Connect-ExchangeOnline` (an undocumented API), and the configuration Exchange Online uses for each domain of the targets; the on-premises commands to run for a source on-premises.
- **Mailbox services**: folder and message synchronization (delta and deltaLink), own free/busy and MailTips, automatic replies read; with `-AllowWrite`, scheduled 60 days ahead, read back and restored — only when disabled.
- **Provisioning**: user, synchronization from Active Directory, Exchange licenses and plans, mailbox in Exchange Online or not (probe of the Inbox, not read), mailbox type, on-premises mailbox found by Autodiscover.
- **Domain DNS**: MX, SPF (includes followed, DNS lookups counted), Autodiscover, DKIM, DMARC, MTA-STS with its policy file, TLS-RPT, device registration; then the domain in the tenant and the records Microsoft 365 expects for it, compared with the DNS.
- Clouds `Global`, `USGov`, `USGovDoD`, `China`.
- Microsoft Graph good practices: `client-request-id` / `return-client-request-id`, `$select` of the properties needed, throttling (HTTP 429 / 503 / 504 with `Retry-After`, `Test.MaxRetries`), the Graph server from `x-ms-ags-diagnostic`.
- **Traceability**: every HTTP request and response and every DNS query in the report, attached to the check that sent it; tokens, assertions, codes and cookies masked.
- Console, daily log, CSV (`Steps`, `Mailboxes`, `FreeBusy`, `Events`, `Provisioning`, `Dns`, `Actions`, `Trace`), `Summary.json` and a self-contained HTML report; WPF window (`-Gui`). Exit codes `0` passed, `1` failed, `2` warnings or blocked.
- Pester tests without connection (`Run-Tests.ps1`), GitHub Actions validation on PowerShell 7.
- Documentation: a **user guide** (prerequisites and everyday commands) and a **developer guide** (how it works, inputs and tests, clients and permissions, configuration, report and trace, troubleshooting, architecture), in Markdown and as self-contained HTML (`tools\Build-Documentation.ps1`); README graphics in light and dark (`tools\New-ReadmeImages.ps1`); release zip (`tools\New-GraphConnectivityTestsPackage.ps1`).
